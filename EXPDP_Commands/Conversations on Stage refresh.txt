How Oracle impdp Works?

Oracle Data Pump Import (impdp) is a utility that loads data and metadata from dump files created by expdp (Data Pump Export). By default, impdp will attempt to import all objects from the dump file, including:
•	Tables
•	Views
•	Stored Procedures
•	Functions
•	Packages
•	Sequences
•	Triggers
•	Jobs
•	Object Grants

We chose an option Table Import with TABLE_EXISTS_ACTION=REPLACE

When using the TABLE_EXISTS_ACTION=REPLACE parameter for tables:
•	If the table exists in the target: The table will be dropped and recreated with the data from the dump file
•	If the table does NOT exist in the target: The table will be created fresh from the dump file
•	Important: This parameter only affects tables that exist in BOTH the dump file AND the target database
•	It will NOT drop tables that exist only in the target (Stage) but not in the source (Prod) dump file

Handling Stored Procedures and Other Objects
For stored procedures and other schema objects, you have more granular control:
Option 1 - Clean up procedures in Stage before import:
•	Drop the procedures manually in Stage
•	Then run impdp, which will create them fresh from the dump file
Option 2 - Exclude procedures from import:
•	Use the EXCLUDE parameter to skip procedures entirely 
•	If you need to replace procedures later, you'll need to clean them up first in Stage, then run a separate import

If you try to import procedures that already exist in the target database, impdp will throw an errors ( Object already exists ) and it will not over ride with production, The same is applicable for Views, Sequences,Jobs

Customizing Imports with EXCLUDE/INCLUDE :

You can exclude specific object types using the EXCLUDE parameter:

-- Exclude stored procedures
EXCLUDE=PROCEDURE

-- Exclude multiple object types
EXCLUDE=PROCEDURE,FUNCTION,PACKAGE
